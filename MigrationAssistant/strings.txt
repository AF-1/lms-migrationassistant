	EN	Restore

PLUGIN_MIGRATIONSASSISTANT_SETTINGS_RESTORE_INTRO
	EN	<b>Use at your own risk.</b> This is an experimental feature. <span style="color:red;">Please create your own backup of all relevant files beforehand.</span><br><br>Before restoring, you can preview the archive's contents and choose exactly which items to restore.<br><br>Restoring onto a freshly installed server? Let the initial library scan complete first, then install the plugins you want to use, and only then restore from your backup.<br><br>After restoring, you need to restart Lyrion Music Server manually for the changes to take effect. If any of the restored settings require a media library rescan, you'll be told so after the restore and need to trigger one manually afterwards.

PLUGIN_MIGRATIONSASSISTANT_SETTINGS_RESTORE_SKIPPREFS
	EN	Skip preferences during restore (optional)

PLUGIN_MIGRATIONSASSISTANT_SETTINGS_RESTORE_SKIPPREFS_DESC
	EN	Comma-separated list of preferences to always skip when restoring, in the format <i>namespace:prefname</i>.<br>Useful e.g. when migrating a server to a different platform or replicating preferences across multiple server instances, to avoid overwriting values that must stay unique or environment-specific per instance.<br><br>The following server values are always skipped by default, regardless of this list: server UUID, cache/database paths, security secret, bind address, media folder(s), playlist folder. The data folder path preferences of Alternative Play Count, Custom Skip, Dynamic Playlists, Dynamic Playlist Creator, Ratings Light and Virtual Library Creator are skipped by default as well, since Migration Assistant restores their contents to a new location automatically.

PLUGIN_MIGRATIONSASSISTANT_SETTINGS_RESTORE_CREATEBAKS
	EN	Create .bak files when overwriting existing files

PLUGIN_MIGRATIONSASSISTANT_SETTINGS_RESTORE_CREATEBAKS_DESC
	EN	When restoring files that already exist on a system (playlists, plugin data folders, custom paths, log.conf, custom graphics/HTML/IR files and preference files), Migration Assistant keeps one timestamped .bak copy of the previous version by default. Disable this if you don't want these BAK copies (e.g. to save disk space) - existing files will be overwritten directly and cannot be recovered afterwards.
